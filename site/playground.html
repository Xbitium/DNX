Watch a name become an address — twice.

DNX completed a wire-format migration: the original 32-byte fixed address and the namespace path ran concurrently on the production routers, then the registry became the identifier authority, and then the old format was deleted — a router asked for a fixed-address frame today refuses it by name. This page keeps both formats runnable because the migration is the story: type any name below and see it rendered as each, the retired format included. Everything here is computed in your browser by the same rules the implementation uses — the hashed fields are real SHA-256, truncated exactly as the Go code does it, and the path identifiers come from a faithful port of the same allocator. Nothing on this page is a mock-up.

1 · The name

Everything below reacts to this one field.

2 · As a fixed address — 32 bytes, the original format, now retired

Four 64-bit fields. The top two are assigned by a registry, which is what makes routes aggregate. The bottom two are derived from the label by hashing, so anyone can name their own hosts without asking permission. Every field is the same width whether it needs to be or not — that uniformity is what costs the bytes, and it is also what makes the format need no coordination at all: a hashed label is identical on every machine that computes it. And four tiers is a hard wall: a deeper name is refused outright, because until defect 10 the encoder silently dropped the labels it had no field for — two distinct deep names, one identical address, no error anywhere. Try the "deeper than 4 tiers" preset above and watch each format answer for itself. This format no longer exists on the wire: the production routers refuse a 0xDF frame by name, and this section is its museum exhibit — kept runnable because it is the second implementation that caught defect 5, and the one defect 10 was demonstrated against.

Change a single character of the host label and watch the bottom field change completely — that is the avalanche property of the hash. Change the domain and only the assigned field moves.

3 · As a namespace path — usually far shorter

The same name, numbered instead of hashed. Each level gets an identifier that only has to be unique among its siblings, so the numbers stay small and the whole destination is one length byte plus four bytes per level. A four-level name fits in 17 bytes where the fixed address always needs 32.

fixed address 32 bytes
namespace path 17 bytes
What the shorter format costs

Density is not free. A hash is the same everywhere, so any machine can derive a fixed address for any name with no agreement whatsoever. A parent-scoped number is only meaningful if everyone agrees on it — and nothing distributes these yet. Today they are assigned by hand, in matching order, in every node's config. Section 10.3 of the whitepaper records this as an open weakness, and it is the single thing standing between the two formats and retiring the older one.

4 · Follow it through the network

This walks the destination through the same four-router topology running live on two datacenters right now. Each hop reads exactly one level and nothing else. Switch the format and watch the same routers forward either encoding — which is how the migration actually ran: both formats concurrently, no cutover, until the old one had no reason left to exist and was deleted. The simulator keeps the dual walk as the record of how a wire format leaves a network without a flag day.

5 · On the wire

Both frames, byte for byte. The payload is sealed before the routing header is attached, which is why routers can forward what they cannot read — and why the same sealed bytes ride under either header without caring which one it is.

6 · Where the numbers come from

Identifiers are handed out one at a time, in the order names are first seen, and only ever within a single parent. That is what keeps them small. It is also a hazard, and this is the honest demonstration of it: reorder the list below and watch the paths change. Every node on the network derives these independently from its own configuration, so two nodes given the same names in a different order will disagree — and a router that disagrees does not fail loudly. It forwards, confidently, to the wrong place.

the two nodes now disagree

The fixed address has no equivalent hazard — hash64("host1") is 0xc0365b5a3867cc38 on every machine that has ever computed it, in any order, forever. That property is exactly what the 32 bytes were buying.

7 · Why the core does not grow

The claim DNX is built on is that adding hosts should not enlarge the tables near the root. Drag the slider and watch: the leaf switch learns every host, and the core learns nothing at all. It already knows where .com is, and that is the only question it is ever asked.
